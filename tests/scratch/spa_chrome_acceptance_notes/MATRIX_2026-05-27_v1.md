**Browser:** Chrome via DevTools MCP, port 9222.
**SPA:** localhost:5173 (Vite frontend) + localhost:8000 (FastAPI backend).
**Model floor:** anthropic:claude-sonnet-4-6 OR openai:gpt-5.4-mini.
**Acceptance discipline:** per `kaos-modules/docs/guides/mcp-testing.md`
— real LLM providers, no mocking, four-signal capture per turn
(snapshot + console + network + cost), assert on domain content not
length, fail loudly on `is_error=true`.

## Scope

This matrix is the **SPA-level** equivalent of the wire-test discipline
the guide prescribes for stdio MCP tools. The unit of test is one
user-visible flow through the rendered React UI, hitting the FastAPI
backend, hitting real LLM providers. Each scenario records:

1. **Snapshot** — the a11y tree of the page at completion, with the
   final assistant text + tool-trace activity panel state.
2. **Console** — any errors / warnings emitted to the browser console.
3. **Network** — the request path that fired (upload POST, message POST,
   citations POST, vfs GET, etc.) and the response code.
4. **Cost** — the per-turn cost + token count surfaced via
   `TurnSummary` + the `cost_usd_so_far` event.

A scenario PASSES only when:
- The final assistant text contains the expected domain content
  (verbatim quote, citation marker, named entity, etc. — NOT just
  "len > 0").
- No tool call returned `is_error=true` in the Activity panel.
- The cost stayed within the per-turn cap.
- The console has no unexpected errors.

A scenario FAILS-degraded if a partial-but-honest answer surfaces
(e.g. refusal text from the no-evidence gate with the new quantified
wording is a documented honest-failure, not a regression).
